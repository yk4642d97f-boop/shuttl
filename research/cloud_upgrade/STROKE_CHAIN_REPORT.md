# 击球检测与球种分类联测

日期：2026-10-07。权重固定为已选出的 HitNet 候选与原 BST seq30 十模型 logits 集成。
本轮没有重新训练 BST，也未根据测试集结果调整任何权重。

## 固定协议

旧基线：原三模型 HitNet，BST 窗口使用手机当前的 +2 帧补偿。
候选：新 HitNet；先在验证比赛 041 比较 +2 帧与不补偿，再冻结不补偿方案。
另一验证比赛 033 尚无 RTMPose 特征，本次不能把单场验证描述成两场验证。
验证联合 F1：原链路 83.21%，新模型 +2 帧 84.45%，新模型不补偿 84.71%。
选择记录在 `stroke_chain/selection.json`，随后才运行测试。

同一套 RTMPose 特征、同一 BST 十份权重、固定一秒窗口；击球与标签在 ±2 帧内
一对一匹配，不允许两个预测重复命中一个标签。
联合指标同时惩罚漏检、误报和球种错误；缺少姿态或模型拒识不会从标签分母消失。
未知球种标签不计球种分母，但仍参与击球时刻检测指标。

数据中还存在同一帧被赋予不同球种的冲突：测试涉及 23 个事件。
这些事件明确标记为球种未知，保留在检测指标中；没有随意取 CSV 的第一条或最后一条。
事件级 JSON 保留原冲突类别，便于人工复核。

|---|---:|---:|

| 已匹配且可分类片段的球种准确率 | 85.20%（3,075 片段） | 86.01%（3,116 片段） |

| 比赛 | 原联合 F1 | 新联合 F1 |

总计 3,499 个标注击球，其中 3,320 个有可用球种标签。新链路多正确识别 60 次。
五场比赛的联合 F1 均提升，按比赛成对 bootstrap 的增量 95% 区间约为
+0.93～+1.93 个百分点。样本只有五场，且历史上已使用过，不代表新场馆泛化区间。

25 类“半场 + 球种”联合计数与仅球种计数在这次测试中恰好相同；
不能外推成所有视频中半场判断永不出错。

## 验证与限制

- 抽取 25 个既有参考片段，joints / pos / shuttle 三种输入最大差异均为 0。
- 所有比赛的击球计数与前一轮 HitNet 独立报告完全一致。
- 检查了重复预测、错误球种、拒识、未知标签及上下半场混淆的计分行为。
- `stroke_chain/verification.json` 保存实现、原始提取和姿态文件 SHA256；保存了评测代码快照。
- **这是标注单打回合中的两个模型联测，不是完整 App 端到端准确率。**
  尚未包括连续休息段误报、自动回合分割、3D、计分、真实手机场馆、双打和 CUDA。
- 本轮联测采用训练参考的正确球员顺序。随后发现手机 HitStage 顺序错误，
  因此这里的“原链路”是模型参考基线，不能当作有该错误的手机版本的实测分数。

运行入口：`stroke_chain.py`。原始结果：`stroke_chain/val.json`、`stroke_chain/test.json`、
每场 `*_events.json`。已消费测试结果，不再按这些比赛继续筛选模型。
