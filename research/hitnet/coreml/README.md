# hitnet -> CoreML

Exports the shipped learned hit detector as a single CoreML mlprogram and proves it matches
PyTorch, then dumps golden fixtures for the Swift port.

Everything here is generated by the three scripts in this directory; nothing outside
`research/hitnet/coreml/` is written.

```
/path/to/shuttl/research/coreml/venv/bin/python convert_hitnet.py   # -> HitNetDetector.mlpackage
/path/to/shuttl/research/coreml/venv/bin/python parity_hitnet.py    # -> parity.json
/path/to/shuttl/research/coreml/venv/bin/python make_fixtures.py    # -> fixtures/*.npz, fixtures/index.json
/path/to/shuttl/research/coreml/venv/bin/python score_official.py  # -> out_coreml/*.hits.json, score_official.json
```

## The model that is shipped

`REPORT.md`'s "3-TCN logit-average ensemble" — the best test variant (`ckpt/tcn_s0.pt`,
`ckpt/tcn_s1.pt`, `ckpt/tcn_lr.pt`; seeds 0, 1, 3). Whole-rally, non-causal: the net is a
bidirectional dilated TCN, so it sees the entire rally at once. Decoder `thr 0.4`, `gap_s 0.30`,
`lam 0` (no alternation), trained/tuned in the parent repo; the CoreML file only replaces the
network, not the decoding.

The graph averages the 3 members' logits **inside** the model, so `4x` files become one
`.mlpackage` and the app never sees the ensemble. `HitNetDetector.mlpackage` is 5.3 MB
(`weight.bin` 5.41 MB fp32 = 3 × 454 658 params = 1.364 M, exactly the ensemble REPORT.md prices).

### Input / output

| | name | shape | dtype | meaning |
|---|---|---|---|---|
| input | `features` | `(1, T, 51)` | float32 | one row per video frame, from `common.derive(raw, fps)` |
| output | `logits` | `(1, T, 2)` | float32 | raw pre-softmax `[hit, hitter-is-far]` per frame |

`T` is dynamic (`RangeDim(1, 4096)`; the longest rally in the held-out matches is 1328 frames, the
shortest 241). One `predict()` call per rally. Everything is fp32 — fp16 was catastrophic for the
sibling BST port (12–54% argmax flips) and this decoder thresholds probabilities, so fp16 is not
shipped.

Correction for long rallies (only if the app wants bit-certainty with the measured numbers): the
reference pipeline runs overlapping 384-frame windows with stride 192 and keeps the centre 192
frames of each; on real rallies that costs at most 0.105 logit versus the whole-rally call and
changes 1 detection out of 3327 (see *Parity*). Both spellings use the same graph.

## Decoding (Swift must reproduce this exactly)

`common.detections_from_logits`, with `logits` from CoreML, `frames` = the rally's video frame
indices, `fps` = the match's fps:

1. `p = sigmoid(logits[:,0])` — hit probability; `st = sigmoid(logits[:,1])` — P(hitter is far/Top).
2. `local_peaks(p, 0.4)`: index `i` with `p[i] > p[i-1]` **and** `p[i] >= p[i+1]` and `p[i] >= 0.4`
   (missing neighbours treated as `-1`, so the first/last frame can be a peak).
3. `decode_nms`: sort those peaks by descending `p` (stable), greedily keep a peak when it is at
   least `gap = max(1, round(0.30 * fps))` frames from every already-kept peak; return sorted.
4. Each kept `i` -> `frame = frames[i]`, `t = i / fps`, `confidence = p[i]`,
   `hitter = "far" if st[i] > 0.5 else "near"`.

`lam > 0` selects the alternation DP instead, but the shipped default is `lam 0` and the DP is not
part of this port.

## Parity (`parity.json`)

426 rallies / 188 369 frames of the 5 held-out matches (039 040 042 043 044), CoreML whole-rally vs
PyTorch — reference = `infer.predict_windowed` 384/192, fp32, CPU, the exact pipeline behind the
0.9212 headline. Detection agreement is compared after sigmoid + threshold + NMS.

| setting | max abs logit diff | graph-only max diff | frame-clf agree | detections | frames exact | F1@±2 | ms/clip |
|---|---|---|---|---|---|---|---|
| CPU_ONLY | 1.05e-01 | 9.5e-06 | 0.999997 | 3327 vs 3327 | 3326 (+1/-1) | 0.9212 | 17.4 |
| CPU_AND_NE | 1.05e-01 | 9.5e-06 | 0.999997 | 3327 vs 3327 | 3326 (+1/-1) | 0.9212 | 17.6 |

The 1.05e-01 is **not** the export's error: it is the documented windowed-vs-whole-rally difference
(REPORT.md: max |Δ| 0.316, mean 0.019). Run the same whole-rally spelling on both sides and the gap
is 9.5e-06 — i.e. the mlprogram reproduces the fp32 network. `CPU_AND_NE` offers nothing here (small
1-D convolutions, no ANE wins), so ship CPU as the compute unit and treat NE as harmless.

Decoder margin: across the 5 matches the closest any frame comes to the 0.4 hit threshold is
1.9e-05 in probability, and 54 of 188 369 frames sit within 1e-3 of it. The graph's own error
(≈1e-05) is at the edge of that first gap, which is why the single differing detection exists; a
port that drifts by more than ~1e-4 in probability can be expected to start flipping isolated
detections near the threshold. Compare logits before comparing detections.

**Held-out reproduction, official scorer** (`research/hits/score.py`, CSV labels, shift 0):
`score_official.py` writes `out_coreml/NNN.hits.json` in `infer.py`'s schema and scores both sides
through `evaluate.tally`; results in `score_official.json`. CoreML: F1@±2 `0.9212`
(P 0.9450 / R 0.8985), tp/fp/fn `3144/183/355`, 3327 detections, ±1 `0.8286`, ±4 `0.9473`, serve
recall 215/426, non-serve 2929/3073. Per-match F1@±2: 039 `0.8852`, 040 `0.9266`, 042 `0.9382`,
043 `0.9221`, 044 `0.9376` — **every one of these equals the stored `out/ens3_windowed` PyTorch
output and REPORT.md's 0.9212.** The only difference anywhere in the five matches is one detection
in 044: its matched offset moves from −2 to −1 (offset histogram `0:1493 −2:97` for CoreML vs
`0:1492 −2:98` for torch), which is why ±1 reads 0.8286 vs 0.8283. Pooled tp/fp/fn and all three
tolerances at ±2 and ±4 are bit-identical; that single frame is the detection parity counts as
"+1/−1" at ±0.

## Fixtures (`fixtures/`)

Ten real rallies spanning all five held-out matches, longest and shortest of each pool included.
Each `.npz` is self-contained: a Swift port re-derives the 51 features from `raw` + `fps` alone,
runs the model, and compares against the stored reference logits. No video, no keypoints.

| array | shape | dtype | meaning |
|---|---|---|---|
| `raw` | `(T,16)` | float32 | the normalised per-frame inputs `derive()` reads; `NaN` = missing |
| `features` | `(T,51)` | float32 | `common.derive(raw, fps)` — the model input |
| `logits` | `(T,2)` | float32 | PyTorch reference, 3-checkpoint ensemble, whole rally, fp32 CPU |
| `logits_windowed` | `(T,2)` | float32 | same models through `infer.predict_windowed` (384/192, centre-only) |
| `coreml_logits` | `(T,2)` | float32 | what the shipped `.mlpackage` returned (CPU_ONLY), for provenance |
| `fps` | scalar | float64 | match fps: 30.0 (040/043/044 carry 29.9989/30.0000 floats) |
| `frames` | `(T,)` | int64 | video frame index of each row (e.g. 11756…12043) |
| `hits` | `(H,)` | float64 | labelled hit positions, in row indices (`t`), not video frames |
| `side` | `(H,)` | int64 | 1 = hitter is Top/far, 0 = Bottom/near, −1 = unknown |
| `set`, `rally`, `n_frames` | scalar | int64 | ShuttleSet set number, rally id, `T` |

`fixtures/index.json` lists every rally with its `T`, match, fps, hit count, first video frame, and
the CoreML-vs-torch max diff for both spellings. `features`/`logits` are the arrays the port must
match; `raw` + `fps` are what it consumes.

### `raw` columns (T,16)

Produced by `common.build_cache()` (common.py:88–105) from `research/extract/out/NNN.npz`.

| col | name | units | `NaN` when |
|---|---|---|---|
| 0 | shuttle x / W | 0..1 (W = 1280, already divided) | shuttle not visible (`shuttle_visible` false or non-finite xy) |
| 1 | shuttle y / H | 0..1 (H = 720) | shuttle not visible |
| 2 | shuttle tracker confidence | 0..1 | shuttle not visible |
| 3 | shuttle interpolated flag | {0,1} | never (unmasked column) |
| 4–7 | player 0 box centre x/W, centre y/H, width/W, height/H | 0..1 | player 0 box non-finite |
| 8–11 | player 1 box, same four | 0..1 | player 1 box non-finite |
| 12–13 | player 0 ankle-midpoint world x, y | metres, court-centred frame | player 0 foot unresolved |
| 14–15 | player 1 ankle-midpoint world x, y | metres | player 1 foot unresolved |

Missing is `NaN`, never 0 — a Swift port must keep the distinction (0 is a legal shuttle x and a
legal box width).

### `features` channels (T,51)

Built by `common.derive(raw, fps)` in this order. `ps = fps/30`; `c(a,k) = clip(nan_to_zero(a)*k,
-6, 6)`; `_fwd/_bwd/_cen/_acc` are the forward / backward / central / second finite differences
(the first/last frame of a one-sided difference is `NaN`, hence the validity flags). Shapes were
verified channel-by-channel against the real fixtures.

| idx | name | definition |
|---|---|---|
| 0,1 | shuttle x, y | `raw0`, `raw1`, 0 where missing |
| 2 | shuttle visible | 1 if `raw0` finite |
| 3 | shuttle interp | `raw3`, 0 where missing |
| 4 | shuttle conf | `raw2`, 0 where missing |
| 5,6 | forward Δx, Δy | `c(_fwd(sx), 30·ps)`, `c(_fwd(sy), 30·ps)` |
| 7,8 | backward Δx, Δy | `c(_bwd(sx), 30·ps)`, `c(_bwd(sy), 30·ps)` |
| 9,10 | central Δx, Δy | `c(_cen(sx), 30·ps)`, `c(_cen(sy), 30·ps)` |
| 11,12 | second difference Δ²x, Δ²y | `c(_acc(sx), 100·ps²)` |
| 13 | speed | `c(hypot(_cen(sx), _cen(sy)), 30·ps)` |
| 14 | direction-change cosine | `dot(_bwd,_fwd) / max(‖_bwd‖·‖_fwd‖, 1e-6)`, then `NaN` where the product of norms ≤ 1e-8, else 0; already in [−1,1] |
| 15,16,17 | validity flags | finite(forward Δ), finite(backward Δ), finite(second difference) |
| 18,19 | frames since / until a visible shuttle | `min(i − last_visible, 30)/30`, `min(next_visible − i, 30)/30`; 1.0 when no visible frame exists on that side, so a long blackout saturates at 1.0 instead of growing forever |
| 20–24 | player 0 box: cx, cy, 4·w, 2·h, box-ok | `raw4..7` (w and h scaled ×4 and ×2), ok = cx finite |
| 25,26 | player 0 box centre velocity | `c(_cen(cx), 100·ps)`, `c(_cen(cy), 100·ps)` |
| 27,28 | player 0 foot world x, y | `raw12 / 6.7` (half length), `raw13 / 3.05` (half width) |
| 29 | player 0 foot ok | `finite(raw12)` |
| 30,31 | player 0 foot velocity | `c(_cen(fx), 3·ps)`, `c(_cen(fy), 3·ps)` |
| 32,33 | shuttle-to-box0 offset x, y | `(sx - cx)·(1280/720) / max(h,1e-3)` and `(sy - cy)/max(h,1e-3)`, each `clip(±6)/3`, in box-height units; 0 when not both visible |
| 34 | offset valid | shuttle visible **and** box0 ok |
| 35–39 | player 1 box: same five as 20–24 (from `raw8..11`) | |
| 40,41 | player 1 box centre velocity | as 25,26 |
| 42,43 | player 1 foot world x, y | `raw14/6.7`, `raw15/3.05` |
| 44 | player 1 foot ok | `finite(raw14)` |
| 45,46 | player 1 foot velocity | as 30,31 |
| 47,48 | shuttle-to-box1 offset x, y | as 32,33 |
| 49 | offset valid | shuttle visible and box1 ok |
| 50 | fps/30 | constant, 1.0 for every 30 fps match |

Scaling notes a port will get wrong if it improvises:

- All differences are **per 1/30 s** (× `30·ps`, × `100·ps`, × `3·ps`, × `100·ps²`), so 25 and
  30 fps rallies feed the same net. Every test match is 30 fps, but the fixture `fps` must still be
  used, not assumed.
- Position/kinematic channels are `clip(±6)` after scaling; the offset channels are `clip(±6)`
  **before** `/3`; feature 14 is clipped only to ±1 by construction and is **not** clipped by `c`.
- `NaN` in a difference propagates into its velocity channel until the `nan_to_num` inside `c`, so
  "missing" reaches the net as 0 plus a validity flag — never as a fabricated value.
- Player 0 is far/Top and player 1 is near/Bottom, as written by `RallyExtractor.swift` and read
  by `common.build_cache`. Both outputs depend on the ordered input channels. The former
  near-first description was incorrect; see `research/cloud_upgrade/hit_player_order_audit.json`
  for the validation-only reproduction of the resulting accuracy loss.

### Suggested Swift check

For each fixture: rebuild features from `raw`+`fps`, assert `max|features - npz.features|` is at
fp32 round-off (a derivation bug shows up here, before any weights are involved), run the model on
`features`, assert agreement with `logits` (fp32 tolerance ~1e-4; the fp32 graph vs fp32 torch gap
measured here is ≤ 1e-5), then run the decoder from `logits` and compare detections to
`detections_from_logits(npz.logits, fps, frames, {thr:0.4, gap_s:0.3, lam:0})`.

## Caveats

- Whole-rally inference means the app must hold a complete rally before predicting; the model does
  not stream by itself. The 384/192 window scheme from `infer.py` is the streaming path and is
  supported by the same graph, but its outputs differ from whole-rally logits by up to ~0.1
  (documented, not a defect).
- `fps` is stored per match, not per rally; 040/043/044 store values like `29.9989` / `30.0000`, and
  `ps` inherits that. Use the fixture's `fps` bit-exactly.
- Only the 3-member TCN ensemble is exported. The single-model and no-0910 variants in `ckpt/` are
  not, and `convert_hitnet.py --members` can build any other subset from `ckpt/*.pt`.
- The alternation decoder (`lam > 0`) is not implemented in CoreML — it is a Python-side DP over the
  logits, so if the app ever wants it, it needs the DP in Swift, not a new model.
